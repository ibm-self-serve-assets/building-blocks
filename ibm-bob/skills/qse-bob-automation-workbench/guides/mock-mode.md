# Mock mode guide

## When to use

After `execution-engine.md`. Use for FR-08 and any work on `STREAM_MODE=mock`, `demo.service.ts`, `recorded-run.json`, DEMO labels or the `-DEMO` download names.

## Inputs you need

- `BUILD_DECISIONS.md`: "Demo recording: copied | synthetic" and the G16 decision.
- Mock rows in SPEC 4.1 (Bob), 4.2 (repository), 4.3 (QSE), 4.5 (execution), 4.7 (report) and SPEC 10.1.
- The recording, if the user has agreed to share one. Otherwise generate a synthetic one (Step 3).

## Requirements covered

| ID | Requirement | Acceptance test |
|---|---|---|
| FR-08 | All recorded-replay data is labelled DEMO in the UI and in exports | In mock mode every execution/report/log row has `mock=true`; report Markdown contains the DEMO blockquote; downloads end `-DEMO` (AC-10). |

Companion rule: in `realtime`, a start without Bob fails and never serves demo data (AC-11).

## Steps

### 1. Behaviour contract

| Area | Mock behaviour (status: **Mocked**) |
|---|---|
| Bob connection | Endpoint is the constant `demo://recorded-run`; state always `connected`; key never stored; recorded capabilities returned; save/test/disconnect do not touch the network. Header shows "Bob: Demo - <label>". |
| Repository | No git call; the recorded repository is reported as cloned regardless of the URL entered. `workspaceLabel` is `demo (recorded - no checkout exists)`. |
| QSE CLI | Recorded path and version; no process is started. |
| Execution | `replay()` of the recording, paced by `DEMO_STEP_DELAY_MS` (700), `DEMO_BOB_WAIT_MS` (6000), `DEMO_REPLAY_SPEED` (4). Cancel works mid-replay. Validation (preconditions, prompt length) still applies. |
| Report/artifacts | Served from `backend/demo-data/workspace/`. The analysis is fixed whatever repository or prompt the user enters. |
| Database | Separate file `<DATA_DIR>/db/workbench-demo.sqlite` so demo rows never mix with real rows. |
| Labels | `DEMO_LABEL = "DEMO - recorded data"`; `DEMO_BANNER = "DEMO - RECORDED DATA: this is a replay of a real earlier Headless Bob + QSE CLI execution (STREAM_MODE=mock). Headless Bob, git and the QSE CLI were NOT contacted for this run."` (use "synthetic" wording for a synthetic recording, Step 3). UI: magenta `STREAM_MODE=mock` tag in the header, `DEMO` tag in history and reports, Settings shows "mock - demo, recorded data". |

### 2. Service (`backend/src/services/demo.service.ts`)

- Load `DEMO_DATA_DIR/recorded-run.json` (default `backend/demo-data`). Validate it with zod; if unreadable or invalid, **fail fast** with a clear error naming the manifest path (test: missing recording fails fast).
- Expose: recorded Bob capabilities, recorded repository, recorded QSE config, `replay()` producing the step/log/event stream, and file reads for artifacts guarded by `isInside`.
- Adapter factory throws `demo_mode` when asked for a real adapter unless `STREAM_MODE=realtime`.
- Every persisted row created in mock mode carries `mock=true`.

### 3. `recorded-run.json` schema (schema 1)

```text
schema: 1
description: string
recordedFrom: { executionId, startedAt, finishedAt, durationMs, headlessBobRunId, headlessBobThreadId, adapter: "rest-threads"|"acp" }
repository:   { url, owner, name, branch, commit, fileCount }
qse:          { executablePath, version, versionArgs: string[] }
bobCapabilities: { adapter, runtimeReady, features{streaming,cancellation,fileDownloads,threads,continuation}, limits{timeoutMs,maxMessageCharacters,maxConcurrentRuns,maxDownloadBytes} }
prompt: string
reportFile: "qse-e2e-report.md"
bobEvents: [ { offsetMs: number, text: string } ... ]
files:     [ { path, contentType, file (relative to demo-data), size } ... ]
```

The reference recording has 159 events and 4 files (report plus three QSE result JSONs under `qs_scan_result_run2/qs_explorer_result/`), recorded duration 253 273 ms. Local paths in it were replaced with placeholders.

**If no recording is shared, generate a synthetic one:**

1. Set `recordedFrom.executionId` to a fresh uuid, `adapter` to `rest-threads`, and add `"synthetic": true` as a comment-style note in `description` (for example "SYNTHETIC recording generated by the skill pack; not a real scan").
2. Use an obviously fake repository (`owner: "example"`, `name: "sample-app"`, a fake 40-hex commit) and a small `bobEvents` list (10-20 events) whose text is generic Markdown with the six deliverable sections.
3. Create `workspace/qse-e2e-report.md` containing the same sections and a first line stating it is synthetic.
4. **Never invent results that look like a real customer scan** (no real library names presented as findings, no fake CVEs, no risk scores). Keep findings generic and say "synthetic".
5. Make the DEMO banner say "SYNTHETIC DEMO" instead of "replay of a real earlier execution".

### 4. G16 default

Reference default is `mock` (env.ts and compose). Faithful clone: keep it, and make the header chip and Settings tag unmistakable. If BUILD_DECISIONS says "fix", require an explicit `STREAM_MODE` in compose and the deploy scripts.

## Verification (exit gate)

```bash
cd backend && npm test
```

Tests required (mirror the 10 reference demo tests): mock replay completes; default config is mock; validation still applies; setup is required in realtime; cancel mid-replay; missing recording fails fast; realtime never serves demo data (4 cases).

- FR-08 statement: query the demo DB after a replay and assert every row has `mock=true`; download names end `-DEMO`; report contains the banner (AC-10, AC-11).
- Confirm no network call is made in mock mode (the fake Bob server records zero requests).

## Pitfalls

- Mixing demo and real rows in one database file.
- Letting any UI text imply the demo was a live scan.
- Copying a real repository name, commit or customer data into a synthetic recording.
- Allowing an absent recording to silently fall back to invented data.
