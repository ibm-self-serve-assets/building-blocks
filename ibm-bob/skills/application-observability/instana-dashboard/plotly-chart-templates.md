# Mandatory Plotly Chart Templates

All **new** Application Observability dashboards generated by this skill must use Plotly for charts.

> **Existing dashboards using `@carbon/charts-react`** (e.g. Lab1c): retain `@carbon/charts-react` — do not replace it with Plotly unless explicitly instructed. When enhancing an existing dashboard, match the chart library already in use. The required **chart titles and layout positions** are the same regardless of chart library.

## Installation (new dashboards)

```bash
npm install plotly.js react-plotly.js
```

> ⚠️ **Source map warnings**: Add `GENERATE_SOURCEMAP=false` to `package.json` start/build scripts.

## @carbon/charts-react equivalent (existing dashboards)

When working with an existing `@carbon/charts-react` dashboard, map the 5 required charts as follows:

| Spec chart | @carbon/charts-react component |
|------------|-------------------------------|
| Top Services by Calls (H-Bar) | `SimpleBarChart` |
| Top Services by Latency (H-Bar) | `SimpleBarChart` |
| Top Endpoints by Calls (H-Bar) | `SimpleBarChart` |
| Top Endpoints by Latency (H-Bar) | `SimpleBarChart` |
| HTTP Status / Error Distribution (Donut) | `DonutChart` |

The chart **titles** must match the spec exactly regardless of library.

## Chart 1 — Top Services by Calls (Horizontal Bar)

**File:** `src/charts/ServiceCallsChart.jsx`
**Title:** `Top Services by Calls`
**Type:** Horizontal bar chart

```jsx
// src/charts/ServiceCallsChart.jsx
import Plot from 'react-plotly.js';
import { PLOTLY_LAYOUT_DEFAULTS, PLOTLY_CONFIG } from '../config/plotlyDefaults';

/**
 * @param {{ data: Array<{ service: string, calls: number }> }} props
 */
export default function ServiceCallsChart({ data = [] }) {
  // Sort descending, top 10
  const sorted = [...data]
    .sort((a, b) => b.calls - a.calls)
    .slice(0, 10);

  const trace = {
    type: 'bar',
    orientation: 'h',
    name: 'Calls',
    x: sorted.map((d) => d.calls),
    y: sorted.map((d) => d.service),
    marker: { color: '#0043ce' },
    hovertemplate: '%{x:,.0f} calls<extra></extra>',
  };

  const layout = {
    ...PLOTLY_LAYOUT_DEFAULTS,
    margin: { ...PLOTLY_LAYOUT_DEFAULTS.margin, l: 140 },
    yaxis: {
      ...PLOTLY_LAYOUT_DEFAULTS.yaxis,
      autorange: 'reversed',
      showgrid: false,
    },
    xaxis: {
      ...PLOTLY_LAYOUT_DEFAULTS.xaxis,
      title: { text: 'Calls', font: { size: 10 } },
      tickformat: ',d',
    },
  };

  return (
    <Plot
      data={[trace]}
      layout={layout}
      config={PLOTLY_CONFIG}
      style={{ width: '100%', height: `${Math.max(180, sorted.length * 32 + 40)}px` }}
      useResizeHandler
    />
  );
}
```

## Chart 5 — HTTP Status / Error Distribution (Donut)

**File:** `src/charts/StatusDistributionChart.jsx`
**Title:** `HTTP Status / Error Distribution`
**Type:** Donut (pie with hole)

```jsx
// src/charts/StatusDistributionChart.jsx
import Plot from 'react-plotly.js';
import { PLOTLY_LAYOUT_DEFAULTS, PLOTLY_CONFIG } from '../config/plotlyDefaults';

/**
 * @param {{ data: Array<{ status: string, count: number }> }} props
 *   status — e.g. '2xx', '3xx', '4xx', '5xx', or a specific HTTP status code string
 */
export default function StatusDistributionChart({ data = [] }) {
  // Colour mapping for status groups
  const COLOR_MAP = {
    '2xx': '#198038',
    '3xx': '#0043ce',
    '4xx': '#f1c21b',
    '5xx': '#da1e28',
  };
  const defaultColors = ['#198038', '#0043ce', '#f1c21b', '#da1e28', '#8a3ffc', '#009d9a'];

  const colors = data.map((d, i) => COLOR_MAP[d.status] ?? defaultColors[i % defaultColors.length]);

  const trace = {
    type: 'pie',
    hole: 0.5,
    labels: data.map((d) => d.status),
    values: data.map((d) => d.count),
    marker: { colors },
    textinfo: 'label+percent',
    textposition: 'outside',
    hovertemplate: '%{label}: %{value:,.0f} (%{percent})<extra></extra>',
  };

  const layout = {
    ...PLOTLY_LAYOUT_DEFAULTS,
    margin: { t: 20, r: 20, b: 40, l: 20 },
    legend: {
      ...PLOTLY_LAYOUT_DEFAULTS.legend,
      y: -0.1,
    },
    showlegend: true,
  };

  return (
    <Plot
      data={[trace]}
      layout={layout}
      config={PLOTLY_CONFIG}
      style={{ width: '100%', height: '260px' }}
      useResizeHandler
    />
  );
}
```

## Data Shape Reference

Every chart component expects a specific data shape. The data is prepared by `instanaApi.js` before being passed to the chart.

| Chart | Expected data shape |
|-------|-------------------|
| `CallsChart` | `Array<{ time: string, calls: number }>` |
| `LatencyChart` | `Array<{ time: string, mean: number, p95: number }>` |
| `ErrorRateChart` | `Array<{ time: string, errorRate: number }>` |
| `ServiceCallsChart` | `Array<{ service: string, calls: number }>` |
| `ServiceLatencyChart` | `Array<{ service: string, meanLatency: number, p95Latency: number }>` |
| `EndpointCallsChart` | `Array<{ endpoint: string, calls: number }>` |
| `EndpointLatencyChart` | `Array<{ endpoint: string, meanLatency: number, p95Latency: number }>` |
| `StatusDistributionChart` | `Array<{ status: string, count: number }>` |

`time` values are ISO 8601 strings or formatted locale strings — Plotly accepts both.

## Data Fetching — Verified Field Names (`instanaApi.js`)

> ⚠️ **Verified against live Instana API.** These are the correct field names when fetching from `metrics/services` and `metrics/endpoints`. Using the wrong names produces empty charts with no error.

### Service name field
```js
// ✅ Correct
item.service?.label

// ❌ Wrong — this field does not exist, returns undefined silently
item.service?.name
item.name
```

### Endpoint name field
```js
// ✅ Correct
item.endpoint?.label

// ❌ Wrong — this field does not exist, returns undefined silently
item.endpoint?.name
item.name
```

### Metric request names (applies to ALL metrics endpoints)
```js
// ✅ Correct — metric name is "latency", aggregation carries the statistic
{ metric: 'latency', aggregation: 'MEAN' }   // response key: 'latency.mean'
{ metric: 'latency', aggregation: 'P95'  }   // response key: 'latency.p95'

// ❌ Wrong — returns HTTP 400 "Missing metrics"
{ metric: 'latency.mean', aggregation: 'MEAN' }
{ metric: 'latency.p95',  aggregation: 'P95'  }
```

### Response key reads
```js
// ✅ Correct
item.metrics?.['latency.mean']   // mean latency value
item.metrics?.['latency.p95']    // p95 latency value

// ❌ Wrong — these keys do not exist in the response
item.metrics?.['latency.mean.mean']
item.metrics?.['latency.p95.p95']
```

### Split calls + latency into separate requests
Sending `calls` and `latency` metrics in a single request to `metrics/services` or `metrics/endpoints` causes only `calls.sum` to appear in the response — latency keys are silently absent.

```js
// ✅ Correct — two parallel requests
const [callsRes, latencyRes] = await Promise.all([
  api.post('/api/application-monitoring/metrics/services', {
    ...commonBody,
    metrics: [{ metric: 'calls', aggregation: 'SUM' }],
  }, { signal }),
  api.post('/api/application-monitoring/metrics/services', {
    ...commonBody,
    metrics: [
      { metric: 'latency', aggregation: 'MEAN' },
      { metric: 'latency', aggregation: 'P95'  },
    ],
  }, { signal }),
]);

// ❌ Wrong — latency silently absent in response
api.post('/api/application-monitoring/metrics/services', {
  ...commonBody,
  metrics: [
    { metric: 'calls',   aggregation: 'SUM'  },
    { metric: 'latency', aggregation: 'MEAN' },   // silently dropped
    { metric: 'latency', aggregation: 'P95'  },   // silently dropped
  ],
});
```

### Traces response unwrapping
```js
// ✅ Correct — each item is { trace: {...}, cursor: {...} }
const traces = items.map((item) => {
  const t = item.trace ?? item;                     // unwrap the trace wrapper
  return {
    traceId:     t.id            ?? t.traceId,      // field is 'id', not 'traceId'
    serviceName: t.service?.label ?? '—',           // field is 'label', not 'name'
    endpoint:    t.endpoint?.label ?? t.label ?? '—', // fall back to operation label
    duration:    t.duration      ?? 0,
    erroneous:   t.erroneous     ?? false,
    timestamp:   t.startTime     ?? Date.now(),
  };
});

// ❌ Wrong — accessing flat fields on the wrapper object
const traces = items.map((t) => ({
  traceId:     t.traceId,             // undefined — field is nested under t.trace.id
  serviceName: t.serviceName,         // undefined
  endpoint:    t.endpoint,            // null (it's an object or null under t.trace.endpoint)
}));
```
