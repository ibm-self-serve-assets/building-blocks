# Canonical UI Specification — Application Observability Dashboard

This document is the authoritative, unchanging specification for every Application Observability dashboard generated by this skill. IBM Bob must follow this spec exactly. No section may be omitted, reordered, or redesigned.

---

## 1. Application Header (Mandatory, Unchanging)

| Field | Value |
|-------|-------|
| Title | `Application Observability using IBM Instana` |
| Subtitle | `With IBM Bob and Instana` |
| Component | Carbon `Header` + `HeaderName` |
| Placement | Top of page, fixed |

The header text, Carbon components, and placement are fixed. Do not change them.

---

## 2. Primary Navigation (Mandatory, Unchanging)

Exactly 3 tabs, in this exact order:

| # | Tab Name |
|---|----------|
| 1 | Service Overview |
| 2 | Trace Details |
| 3 | Intelligent Analysis & Insights |

- Carbon `Tabs`, `TabList`, `Tab`, `TabPanels`, `TabPanel` components.

## 3. Service Overview Tab (Mandatory Layout)

### 3.1 KPI Row

5 KPI cards displayed in a single horizontal row in this exact order:

| # | KPI Card Label | Metric Source |
|---|---------------|--------------|
| 1 | Calls / Requests | `calls.count` |
| 2 | Mean Latency | `latency.mean` |
| 3 | P95 Latency | `latency.p95` |
| 4 | Error Rate | `(erroneous_calls / total_calls) × 100` |
| 5 | Affected Services | count of distinct `service.name` values |

- Each KPI card uses `KPICard.jsx` component.
- Card order is fixed — do not reorder.
- If a metric is unavailable, show `—` as the value with a "No data" tooltip. Do not remove the card.
- Status colour logic: Healthy (green) / Degraded (amber) / Error (red) based on thresholds in `analysisService.js`.

### 3.2 Performance Charts — 3 Rows, 2 Columns Per Row

The 3 time-series charts (Calls Over Time, Latency Over Time, Error Rate Over Time) were removed because this Instana instance returns too few time-series buckets for meaningful line charts on sparse traffic. The remaining 5 charts are:

| Row | Left Column | Right Column |
|-----|-------------|--------------|
| 1 | Top Services by Calls (Horizontal Bar) | Top Services by Latency (Horizontal Bar) |
| 2 | Top Endpoints by Calls (Horizontal Bar) | Top Endpoints by Latency (Horizontal Bar) |
| 3 | HTTP Status / Error Distribution (Donut) | *(empty)* |

- Chart types are fixed per the table above. Do not substitute chart types.
- Chart titles are fixed (defined in `dashboardConfig.js` → `charts` array).
- All charts use Plotly (`react-plotly.js`). Do not use Recharts, D3, or Chart.js.
- Each chart is wrapped in `ChartCard.jsx`.
- Charts with no data are **omitted from the DOM entirely** — the empty-data filter in `ServiceOverview.jsx` removes them (unlike other cards, chart tiles are not retained when data is absent).
- Grid layout: `@carbon/react` `Grid` + `Column` with 8/8 split (50/50).

## 4. Trace Details Tab (Mandatory Layout)

Sections appear in this exact order:

### 4.1 Trace Filters

A horizontal filter bar with these 5 controls in order:

| # | Filter | Component |
|---|--------|-----------|
| 1 | Time Range | Carbon `Dropdown` |
| 2 | Service | Carbon `Dropdown` |
| 3 | Endpoint | Carbon `Dropdown` |
| 4 | Minimum Latency (ms) | Carbon `NumberInput` |
| 5 | Error Status | Carbon `Toggle` (All / Errors Only) |

### 4.2 Trace Summary KPI Row

4 KPI cards in this exact order:

| # | Label | Metric |
|---|-------|--------|
| 1 | Total Traces | count of returned traces |
| 2 | Slow Traces | count of traces > p95 latency threshold |
| 3 | Error Traces | count of erroneous traces |
| 4 | Mean Duration | mean trace duration |

### 4.3 Trace Table

Carbon `DataTable` with these columns in this exact order:

| # | Column Header | Field |
|---|--------------|-------|
| 1 | Trace ID | Truncated (first 8 chars + …), clickable button |
| 2 | Timestamp | Formatted local time |
| 3 | Service | `serviceName` |
| 4 | Endpoint | `endpoint` |
| 5 | Duration | `duration` ms |
| 6 | Status | Badge: OK (green) / Error (red) |
| 7 | Error | Error message or `—` |

- Clicking a Trace ID row opens `TraceDetailView.jsx`.
- Row with `erroneous: true` has a subtle red background tint.
- If no traces, show `EmptyState.jsx` in place of the table body. Do not remove the table headers.

### 4.4 Trace Detail View

Displayed as a Carbon `ComposedModal` or side panel when a trace is selected. Contains in order:

1. **Trace ID** (monospace, full value)
2. **Start Time** (formatted)
3. **Total Duration** (ms)
4. **Number of Spans**
5. **Services Involved** (comma-separated list)
6. **Error Status** (badge)
7. **Span Hierarchy** — indented tree of spans (SpanTree component)
8. **Slowest Spans** — top 5 spans by duration, in a mini table
9. Close button + Escape key handler

Do not replace the Trace Detail View with a different visualization (e.g., Gantt timeline only).

## 5. Intelligent Analysis & Insights Tab (Mandatory Layout)

Sections appear in this exact order:

### 5.1 Application Health Summary

A `ChartCard` / info tile summarising:
- Overall health status (Healthy / Degraded / Critical)
- Request volume trend
- Latency assessment
- Error rate assessment
- One-paragraph narrative

### 5.2 Performance Insights

List of identified performance issues. Each item is an `InsightPanel.jsx` card:
- Slow services (services exceeding mean latency threshold)
- Slow endpoints (endpoints exceeding p95 threshold)
- Latency increases (services with increasing latency trend)
- Traffic spikes (services with call count > 2× baseline)

If no performance issues, show: *"No performance degradation detected in the current time window."*

### 5.3 Error Analysis

List of identified error patterns. Each item is an `InsightPanel.jsx` card:
- Services with error rate > 1%
- Endpoints with error rate > 1%
- HTTP 4xx vs 5xx breakdown
- Error rate trend (increasing / stable / decreasing)

If no error issues, show: *"No elevated error rates detected in the current time window."*

### 5.4 Bottleneck Analysis

List of identified bottlenecks. Each item is an `InsightPanel.jsx` card:
- Services with p95 latency > 500ms
- Endpoints with p99 latency > 1000ms
- Long trace durations
- Slow spans (spans contributing > 50% of parent trace duration)
- Dependency chains with cumulative latency > threshold

If no bottlenecks, show: *"No bottlenecks identified in the current time window."*

### 5.5 Recommended Actions

List of actionable recommendations. Each recommendation uses `InsightPanel.jsx` with these 4 fields:

| Field | Description |
|-------|-------------|
| Finding | What was observed |
| Evidence | Specific metric value or trace ID supporting the finding |
| Potential Impact | What could happen if not addressed |
| Recommended Action | Concrete, specific step to take |

Recommendations are generated only from available telemetry. Do not fabricate recommendations.
If no recommendations, show: *"No actionable recommendations at this time."*

## 8. Environment Variables (Mandatory)

All environment-specific configuration must be in `.env` / `.env.local`. Never hard-code these values.

| Variable | Purpose |
|----------|---------|
| `REACT_APP_INSTANA_URL` | Base URL of the Instana unit |
| `REACT_APP_INSTANA_API_TOKEN` | Instana API token |
| `REACT_APP_APPLICATION_ID` | Application Perspective ID |
| `REACT_APP_APPLICATION_NAME` | Display name for the application |
| `REACT_APP_REFRESH_INTERVAL` | Data refresh interval in ms (default: 30000) |
| `REACT_APP_DEFAULT_TIME_RANGE` | Default lookback window in minutes (default: 60) |

---

## 9. Asynchronous Data Fetching (Mandatory)

- All API calls must be `async`.
- Data fetches must not block the UI render.
- `LoadingState.jsx` must be shown while any primary data is loading.
- `ErrorState.jsx` must be shown when an API call fails — not a crash or blank screen.
- `EmptyState.jsx` must be shown when an API call succeeds with zero results.
- Use `AbortController` to cancel in-flight requests when component unmounts or filters change.
- Previously loaded data should remain visible during refresh (do not blank the screen on re-fetch).
- Auto-refresh interval is configured via `REACT_APP_REFRESH_INTERVAL`.

## 11. Dashboard Config (Mandatory)

All layout decisions must be read from `src/config/dashboardConfig.js`. Components must not independently determine their layout.

`dashboardConfig.js` defines:
- `tabs` — ordered array of tab names
- `kpis` — ordered array of KPI definitions for Service Overview
- `charts` — ordered array of chart definitions (title, type, component, grid position)
- `traceColumns` — ordered array of trace table column definitions
- `traceKpis` — ordered array of Trace Details KPI definitions
- `analysisSections` — ordered array of analysis section definitions
- `defaultTimeRange` — default lookback in minutes
- `refreshInterval` — refresh interval in ms
- `thresholds` — latency and error rate thresholds for status colour logic

## 12. Status Colour Thresholds

| Metric | Healthy | Degraded | Critical |
|--------|---------|----------|---------|
| Error Rate | < 1% | 1% – 5% | > 5% |
| Mean Latency | < 200ms | 200ms – 500ms | > 500ms |
| P95 Latency | < 500ms | 500ms – 1000ms | > 1000ms |
| P99 Latency | < 1000ms | 1000ms – 2000ms | > 2000ms |

These thresholds drive the KPI card status indicator colours (green / amber / red).

---

## 13. No-Data and Error States (Mandatory)

| Situation | Behaviour |
|-----------|-----------|
| API call in progress | Show `LoadingState.jsx` inside the card/section |
| API call failed | Show `ErrorState.jsx` inside the card/section; preserve card position |
| API returned zero results | Show `EmptyState.jsx` inside the card/section; preserve card position |
| API token missing/invalid | Show global `ErrorState.jsx` at page level; do not crash |

**Never remove a card or chart when data is unavailable.** The card frame must remain in its defined position.
