Generic Consumer Guide

Using Bobserver Through MCP

This document is for any MCP consumer that wants to call Bobserver on a hosted route. It shows how to connect, how to use the asynchronous bob_prompt_start and bob_prompt_status pattern, and then gives prompt samples for Ansible scripting and remote Vault-backed automation.

1. Generic Bobserver Consumer via MCP

Connection Details

Endpoint

Use the Bobserver route plus /mcp. The UI uses the base route; MCP uses the same route with the MCP path. 

https://<bobserver-route>/mcp

Authentication

MCP clients can use OAuth discovery when supported. Clients that support headers can use Basic auth or a bearer token.

Workspace

Bob Shell runs inside the Bobserver container. Prompts should use explicit paths under /workspace for repeatable work.

Consumer Flow

  1. Connect the MCP client to https://<bobserver-route>/mcp.
  2. Call bob_prompt_start with the prompt, timeout, and yolo setting.
  3. Save the returned jobId.
  4. Poll bob_prompt_status with the jobId and latest offset.
  5. Continue until the job state is completed, failed, or cancelled.
  6. Read the returned summary and inspect any artifacts created under /workspace.

MCP Tools Exposed by Bobserver

Tool When to Use Important Inputs
bob_prompt_start Long-running work. Starts Bob asynchronously and returns a jobId. prompt, timeoutSeconds, yolo
bob_prompt_status Polls an async job for state and new output. jobId, offset
bob_prompt_cancel Cancels a running async job. jobId

Async Pattern: prompt_start then prompt_status

Use the async pattern for anything that may create files, inspect a repo, run tests, call Ansible, or wait on infrastructure. The client starts the job once, then polls for incremental output. 

POST https://<bobserver-route>/mcp
Authorization: Basic <base64(username:password)>
Content-Type: application/json
Accept: application/json, text/event-stream

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "bob_prompt_start",
    "arguments": {
      "prompt": "List the files in /workspace and summarize what this Bobserver can do.",
      "timeoutSeconds": 600,
      "yolo": true
    }
  }
}

The response includes structured content with a jobId and an output offset. Poll with the same job id: 

POST https://<bobserver-route>/mcp
Authorization: Basic <base64(username:password)>
Content-Type: application/json
Accept: application/json, text/event-stream

{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "bob_prompt_status",
    "arguments": {
      "jobId": "<jobId from bob_prompt_start>",
      "offset": 0
    }
  }
}

Continue polling until the state is completed, failed, or cancelled. For each follow-up poll, pass the latest returned offset so the client receives only new output.

Generic Consumer Prompt Samples

These are generic Python-oriented prompts that any MCP consumer can send through bob_prompt_start. They keep all work under /workspace and ask Bob for concrete evidence.

Create a Python Data Summary

Create a Python script at /workspace/python-consumer/summarize_orders.py.

Goal:
- Read /workspace/orders.csv.
- Print row count, columns, total amount, and total amount by region.
- Write a JSON summary to /workspace/python-consumer/orders_summary.json.

Rules:
- Use only Python standard library modules.
- Create the output directory if needed.
- Do not modify the source CSV.
- Run the script after creating it.

        Return:
- Files created.
- Exact command used.
- The JSON summary content.

2. Bob with Ansible Scripting Prompt Samples

These prompts use Bob as an Ansible artifact author, reviewer, or executor. Prefer a review prompt first, then an execution prompt after approval.

Prompt: Create an Ansible Artifact

Create a reviewable Ansible playbook under /workspace/ansible-artifacts.

Goal:
- Check disk usage for localhost.
- Fail only if usage is above 90%.
- Print a concise operator summary.

Rules:
- Use localhost inventory.
- Make the playbook idempotent.
- Do not require SSH.
- Do not print secrets.
- Do not execute the playbook.

Return:
- Files created.
- Exact ansible-playbook command to run.
- Short explanation of the tasks.

Prompt: Validate an Existing Ansible Artifact

Review the Ansible playbook at /workspace/ansible-artifacts/site.yml.

Check for:
- Idempotency.
- Secret leakage.
- Unsafe shell usage.
- Missing validation steps.
- Whether it can run with localhost inventory.

Do not execute it. Return findings first, then the exact command an operator should run after approval.

Prompt: Run an Approved Ansible Artifact

Run this approved Ansible playbook:

ansible-playbook -i /workspace/ansible-artifacts/inventory.ini /workspace/ansible-artifacts/site.yml

Rules:
- Do not print secrets.
- Stop if the playbook fails.
- Summarize changed tasks, failed tasks, and validation evidence.
- Include the exact command that was run.

Certificate Remediation Prompt: Review Only

Read /workspace/cert-demo/bob/ansible_recipe_context.md first.

Validate the proactive certificate-expiry remediation demo.

1. Read the ticket at /workspace/cert-demo/tickets/cert-expiry-ticket.json.
2. Inspect the approved Ansible playbook at /workspace/cert-demo/ansible/rotate-demo-certificate.yml.
3. Confirm whether it uses HashiCorp Vault PKI when VAULT_ADDR and VAULT_TOKEN are configured.
4. Do not print private keys.
5. Summarize the exact Ansible command an operator or AAP job template should run.
6. Explain what evidence proves the remediation succeeded.

Do not execute the playbook.

Certificate Remediation Prompt: Execute After Approval

Read /workspace/cert-demo/bob/ansible_recipe_context.md first.

Run the approved certificate-rotation playbook:

ansible-playbook -i /workspace/cert-demo/ansible/inventory.ini /workspace/cert-demo/ansible/rotate-demo-certificate.yml

Do not print private keys. After it finishes, summarize the issuer, health status, days left, and whether rotation is still required.

3. Using Remote Vault with Bobserver and Ansible

Vault is optional for generic Bobserver use, but it is useful when Ansible automation needs certificates, short-lived credentials, or secrets. The recommended pattern is to inject Vault connection details into the Bobserver pod through platform secrets and let Ansible read them from environment variables.

Environment Contract

  • VAULT_ADDR=https://<remote-vault-host>
  • VAULT_TOKEN=<token from platform secret>
  • VAULT_NAMESPACE=<namespace, if used>
  • VAULT_PKI_MOUNT=pki_int
  • VAULT_PKI_ROLE=edwards-demo-server

Ansible Contract

  • Use community.hashi_vault modules where possible.
  • Read Vault settings from environment variables.
  • Set no_log: true on token, private key, and secret tasks.
  • Return evidence without returning sensitive values.

Remote Vault Prompt Sample

Create a reviewable Ansible playbook under /workspace/ansible-artifacts/vault-pki.

Goal:
- Request a TLS certificate from remote HashiCorp Vault PKI.
- Read VAULT_ADDR, VAULT_TOKEN, VAULT_NAMESPACE, VAULT_PKI_MOUNT, and VAULT_PKI_ROLE from the environment.
- Use common name app.example.com with SAN app.example.com.
- Write the certificate to /workspace/ansible-artifacts/vault-pki/out/app.crt.
- Write the private key to /workspace/ansible-artifacts/vault-pki/out/app.key with mode 0600.

Rules:
- Use community.hashi_vault modules if available.
- Put no_log: true on tasks that handle tokens or private keys.
- Do not print certificate private keys.
- Do not execute the playbook.

Return:
- Files created.
- Required environment variables.
- Exact ansible-playbook command.
- Validation steps that prove the certificate was issued.
